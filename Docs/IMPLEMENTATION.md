# 移动版实现记录

## 当前完成

- 按官方移动版 Mod 结构建立了仓库，入口通过 `GameMain:NewMod` 创建。
- `Scripts/BatchQueue.lua` 实现待执行任务队列：加入、取消、清空、暂停、继续、存档恢复。
- 队列在 `OnStep` 中尝试调用 `BatchActionAdapter`。适配器未接入时不会伪造成功，也不会直接改物品数据。

## 游戏动作适配器约定

需要在目标手游版本中确认 API 后再实现 `BatchActionAdapter`。函数签名：

```lua
function tbMod.BatchActionAdapter(action, actorId, targetId, repeats)
    -- 验证角色、目标、材料、神识/灵气及当前状态。
    -- 只调用游戏原有的炼制或神通逻辑。
    -- 同步成功派发后返回 true；失败时返回 false, "可读原因"。
end
```

队列当前以“游戏已接受一个目标的原版操作”作为推进条件。若原版动作是异步排队，应在手游实机确认接受时机，避免重复派发。炼宝与幽淬/灵淬的校验与派发方式很可能不同，不能共用未经确认的假 API。

## PC 与手游的实现差异

PC 端批量操作可依赖桌面输入、快捷键和原版窗口交互。手游 Mod 由客户端从 Git 仓库拉取，代码与资源须符合移动版的 Mod 目录格式；操作界面需要触屏入口，不能依赖 Ctrl/Shift 快捷键。PC 工坊 Mod 的功能描述可作为需求参考，不能据此推断其内部 API 能在手游使用。
